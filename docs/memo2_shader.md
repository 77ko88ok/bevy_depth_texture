**「なぜBevey（および最新3Dエンジン）はReversed-Zと非線形透視投影を採用しているのか」** という技術的理由と、**「それをそのまま活用すべきか、線形化すべきか」の判断基準や使い分け**
---

### 1. Reversed-Z と非線形透視投影のメリット

Bevyが採用している **Reversed-Z（逆Zバッファ）** とは、従来のグラフィックス手法（カメラ直前＝0.0、遠界＝1.0）とは逆に、**カメラ直前（Near平面）を `1.0`、無限遠（Far平面）を `0.0`** として深度を記録する技術です。

この方式が近代のすべての主要3Dエンジン（Bevy, Unreal Engine 5, Unity HDRP など）で標準採用されているのには、**数学とハードウェア特性を組み合わせた絶妙な戦略的メリット**があります。

#### ① 浮動小数点数（f32）の性質：0.0の近くほど高精度
コンピュータの 32bit 浮動小数点数（`f32`）は、**`0.0` に近づけば近づくほど仮数部の密度が高くなり、圧倒的に精密な精度（分解能）を持つ** という数学的性質（IEEE 754規格）があります。逆に `1.0` に近づくほど精度は粗くなります。

#### ② 透視投影（Perspective Projection）の性質：遠くほど数値が急激に圧縮される
3D空間の距離 \\(z\\) を画面に映す透視変換を行うと、深度値は \\(\frac{1}{z}\\) に比例する非線形な値になります。
* **カメラのすぐ近く**: \\(z\\) のわずかな変化で深度値が大きく変動する。
* **カメラから遠い場所**: \\(z\\) が数十メートル動いても、深度値の変化量は `0.0001` 以下の微小な差にしかならない。

#### ③ 両者が組み合わさった「Reversed-Zの魔法」
従来の方式（Near=0.0, Far=1.0）では、**「一番精度が粗い1.0付近」に「一番変化が微小な遠景のデータ」が追いやられる**という最悪のミスマッチが起きていました。その結果、遠くの山や建物の面が重なってチラつく **Zファイティング（Z-Fighting）** が頻繁に発生していました。

そこで **Reversed-Z（Near=1.0, Far=0.0）** に反転させると：
* **遠くの物体（ Far平面 ≒ `0.0` 近辺）に、浮動小数点の「最も精密な超高精度ゾーン」が割り当てられる** ことになります。

透視変換の数値圧縮と浮動小数点の精度分布がお互いの弱点を完璧に打ち消し合い、**カメラの目の前から数十キロ先の遠景まで、画面全体の深度精度（分解能）がほぼ対数的に均一化される**という絶大なメリットが生まれます。

### 2. 「そのまま（非線形）使う」vs「線形化（Linearize）する」の使い分け

Bevyのレンダラーにおけるこの戦略意図を踏まえた上で、実際のシェーダー開発で**どのような場面でどちらを選択すべきか**の判断基準と例を整理します。

#### 基本原則
* **GPUのパイプラインに任せる描画・深度テスト** ＝ **そのまま（非線形 / Reversed-Z）を活用する**
* **人間が理解できる「メートル単位の物理計算」や「視覚効果」** ＝ **線形化（Linear Depth）して処理する**

---

#### 場面A：そのまま（非線形 / Reversed-Z）を活用すべきケース

GPUの標準機能（Depth Test / Stencil）や、GPU同士で直接計算を完結させるパスでは、Reversed-Zの精度保持能力を100%活かすために非線形のまま扱います。

1. **GPUの標準深度テスト（Z-Test / Depth Prepass）**
   * オブジェクトの前後判定や、遮蔽カリング（Occlusion Culling）。
   * カメラの深度バッファをそのまま使ってポリゴンの重なりを判定する場合は、反転された精度を維持したままGPUにテストを任せるのが最も高速かつ正確です。
2. **シャドウマッピング（Shadow Maps）**
   * ライト視点からの影の生成。シャドウアクティビティでも精度落ちによる影のチラつき（Shadow Acne）を防ぐため、Reversed-Zの精密な深度判定がそのまま使われます。
3. **スクリーンスペース遮蔽（SSAO / GTAO）**
   * 近接するピクセル同士の相対的な落ち込み（影）を計算する際、スクリーン空間上のピクセル差分を直接比較する場合は非線形のままで十分計算できます。

---

#### 場面B：線形化（Linearize Depth）して計算すべきケース

「カメラから何メートル離れているか」に基づいて色や透過率を計算するビジュアルエフェクトでは、シェーダー内で線形化（`0.0 = 近距離`, `1.0 = 遠距離` または実メートル数値）へ変換して処理します。

1. **距離に基づく大気・フォグ（Distance Fog / Atmospheric Scattering）**
   * 「カメラから50m離れたら霧で白くかすませる」といった表現。
   * 非線形のままだとカメラ直前で急激に霧が濃くなってしまいますが、線形化することで「距離に比例したリアルな大気感」を計算できます。
2. **被写界深度（Depth of Field / DoF）**
   * 「カメラから3mの位置にピンボケ（フォーカス）を合わせ、前後をボカす」計算。
   * レンズの物理計算は実際の「メートル（距離）」に依存するため、線形化した深度値を用いて散乱（ボケ幅）を算出します。
3. **水面・水中の深さ表現（Water Depth Fade / Shorelines）**
   * 水面のポリゴン位置と、その奥にある海底ポリゴンの深度差を計算し、「水深が浅い場所は透明・深い場所は濃い青」「水際（岸辺）に白い泡を描画する」エフェクト。
   * 「海底までの実際の深さ（メートル）」を知る必要があるため、海底の深度値を線形化して差分を取ります。
4. **ポストプロセスの等高線・輪郭線（Outlines / Contour Lines）**
   * 今回チャレンジしていただいたような「一定の物理的距離ごとに線を引きたい」「直感的なしきい値（`cutoff_depth`）で画面を色分けしたい」ケース。

---

### まとめ

BevyがReversed-Zを採用しているのは、**広大な3D空間や複雑なシーンでもZファイティングを起こさず、GPU主導で圧倒的に高精度な描画を行うため**という明確な戦略的理由があります。

* **GPUのパイプラインや描画テストに組み込む時**: BevyのReversed-Z構造をそのまま尊重し、GPUに任せる。
* **シェーダー内で「距離」「深さ」「範囲」を使った視覚効果を自作する時**: 今回のようにシェーダー内でサクッと線形化関数（`linearize_depth`）を通して、直感的な `0.0〜1.0`（あるいはメートル単位）に直して計算する。

この役割分担を理解しておくと、今後どんな複雑なカスタムシェーダーやポストプロセスエフェクトを組む際にも迷わずに設計できるようになります！
